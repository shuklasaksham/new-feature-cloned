## TL;DR — the hypothesis (missing/stale secrets or bad callback URLs) is DISPROVEN
The demo/sample sources are **not** a secret or OAuth-config problem. All six OAuth env vars exist and are non-empty in prod, the client IDs match dev, and **all three providers have real, successfully-connected accounts in prod for other users** — proving the client secrets and registered callback URLs are valid end-to-end.

The real root cause is **identity fragmentation**: the Google login `shuklasaksham01@gmail.com` has produced **5 different Bracket `user_id`s** over time (a new one per login). `integration_accounts` is keyed by `user_id`, so connections made under an older identity are invisible to the current session. The account the user is logged into *now* (`user_71792f820e9f`, created 2026-08-31) has **only a gmail connection** — no figma/slack/github rows — so `connectors.list_sources()` correctly falls back to `demo: true` sample data for those three.

## Root cause
Not a secret/config defect. Bracket mints a **new `user_id` on (almost) every Google login** for the same email instead of resolving a stable identity keyed on the Google account. `integration_accounts` is bound to `user_id`, so each new login starts with an empty connection set and only carries whatever the user reconnects in that session. The user's real Slack connection (and any figma/github they may attempt) live on prior, now-orphaned identities; the session they're in today (`user_71792f820e9f`) has none of them, so the pickers show `demo:true` samples.

## Recommended fixes (code/data — owned by E1, not a deploy/secret change)
1. **Stabilize identity on Google login (primary fix):** resolve the Bracket user by a stable key (Google `sub`, or normalized email) and reuse the existing `user_id` instead of creating a new one each login. This is the regression that stranded the connections.
2. **Backfill/merge the fragmented identities** for `shuklasaksham01@gmail.com` (user_8b559b5edf87, user_02ba587fa369, user_f6555538eb63, user_6f49e73a9048, user_71792f820e9f) onto one canonical `user_id` so the existing Slack (and Gmail) connection surfaces — and re-point their `integration_accounts` rows.
3. **Interim user-facing unblock:** the user can simply click "Connect" again on Figma/Slack/GitHub *while logged into the current account*; OAuth will succeed (config is valid) and write fresh `integration_accounts` rows under `user_71792f820e9f`. But without fix #1 this will re-strand on the next fresh login.
